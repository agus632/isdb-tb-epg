# SDT Import Scanner

`scan_sdt.py` analyzes existing MPEG-TS streams and extracts their
**Service Description Table (SDT Actual)** information.

The generated JSON file is intended to be imported by the **ISDB-Tb EPG
SDT Generator**, avoiding the need to manually enter service IDs,
service names, provider names, service types, TSID and ONID values.

The scanner is read-only. It does not modify the input transport
streams.

## What is extracted

For each transport stream:

-   Transport Stream ID (TSID)
-   Original Network ID (ONID)

For each service:

-   Service ID
-   Service type
-   Service name
-   Provider name
-   Running status
-   Free CA mode
-   EIT schedule flag
-   EIT present/following flag

The information is read from PID `0x0011`, SDT Actual, table ID `0x42`.

## Requirements

-   Python 3
-   TSDuck
-   Network access to the MPEG-TS UDP/RTP streams to be analyzed

Verify TSDuck:

``` bash
tsp --version
```

## Configuration

Copy the example:

``` bash
cp inputs.example.json inputs.json
```

Example `inputs.json`:

``` json
{
  "interface": "192.168.1.10",
  "timeout": 5,
  "inputs": [
    {
      "name": "MUX1",
      "address": "239.1.1.1",
      "port": 2001
    },
    {
      "name": "MUX2",
      "address": "239.1.1.1",
      "port": 2002
    }
  ]
}
```

### `interface`

Local IP address used to receive the multicast streams. It can be
omitted when explicit interface selection is unnecessary.

### `timeout`

Maximum number of seconds the scanner waits for an SDT table to be received.

The scanner instructs TSDuck to stop normally after one complete SDT Actual
table has been collected (`--max-tables 1`). Therefore, the timeout is only a
safety limit for cases where no SDT is received, the stream is unavailable, or
the input is incorrectly configured.

For continuously transmitted SDT tables, 5 seconds is normally sufficient.

### `inputs`

Each entry defines one MPEG-TS input:

-   `name`: Friendly name for the multiplex.
-   `address`: UDP multicast address.
-   `port`: UDP port.

There is no fixed limit on the number of multiplexes.

## Scan

``` bash
python3 scan_sdt.py \
  --config inputs.json \
  --output sdt-import.json
```

## Output format

The scanner converts TSDuck's representation into a stable import format
used by this project:

``` json
{
  "format": "isdb-tb-epg-sdt-import",
  "version": 1,
  "source": {
    "tool": "TSDuck",
    "table": "SDT Actual",
    "table_id": 66,
    "pid": 17
  },
  "muxes": [
    {
      "name": "MUX1",
      "transport_stream_id": 14,
      "original_network_id": 14,
      "services": [
        {
          "service_id": 32,
          "service_type": 1,
          "service_name": "Example Channel HD",
          "provider_name": "Example Provider",
          "running_status": "running",
          "free_ca_mode": false,
          "eit_schedule": false,
          "eit_present_following": false
        }
      ]
    }
  ]
}
```

## Why use an intermediate format?

TSDuck internally represents PSI/SI tables using its own XML/JSON model.
This scanner converts that representation into a small, stable format
specific to the ISDB-Tb EPG project.

The SDT Generator therefore does not depend directly on the internal
JSON layout generated by a particular TSDuck version.

## EIT flags

The scanner preserves the original SDT values of:

-   `eit_schedule`
-   `eit_present_following`

Importing an SDT does not automatically change these values. The SDT
Generator can later configure them according to the EIT services
generated by the system.

## Validation and errors

Each imported service must contain:

-   Service ID
-   Service descriptor
-   Service type
-   Service name
-   Provider name

Missing required information is reported as an error instead of being
silently invented.

If some multiplexes succeed and others fail, valid multiplexes are still
written to the output file.

### Exit codes

-   `0`: All inputs successfully scanned.
-   `1`: Fatal error or no usable SDT.
-   `2`: Partial scan; one or more inputs failed.

## How the capture works

For each configured input, the scanner uses TSDuck to:

1. Open the MPEG-TS UDP/RTP input.
2. Listen to PID `0x0011`.
3. Filter SDT Actual (`table_id 0x42`).
4. Collect one complete SDT table.
5. Stop TSDuck normally using `--max-tables 1`.
6. Read the JSON representation generated by TSDuck.
7. Validate and convert it to the stable ISDB-Tb EPG import format.

The configured timeout is used only as a safety mechanism if TSDuck cannot
receive a complete SDT.

## Import into the application

Before modifying the database, validate the generated file:

```bash
python3 import_sdt.py --check sdt-import.json
```

If validation succeeds, import the SDT configuration:

```bash
python3 import_sdt.py sdt-import.json
```

The importer matches each multiplex using its Transport Stream ID (TSID)
and Original Network ID (ONID).

The import file represents a complete SDT snapshot for each included
multiplex. Existing SDT services for those multiplexes are replaced by
the services contained in the import file.

If an SDT configuration does not yet exist for a multiplex, it is created
disabled. The generator must be enabled explicitly after reviewing the
imported configuration.

## Notes

The scanner reads **SDT Actual** (`table_id 0x42`) from PID `0x0011`.

The source transport stream remains unchanged. The tool only listens to
the stream and extracts SDT metadata.

The generated file provides initial configuration for the SDT Generator.
Once imported into the application database, the generator does not need
continued access to the original transport stream.

## Security and privacy

The generated import file contains SDT service metadata such as channel
and provider names.

Multicast source addresses and the local interface address are **not**
stored in the generated import file.

Review the generated JSON before publishing it if service or provider
names contain information you do not want to make public.
